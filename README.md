# Caelogix — Marketing Website

A full-stack marketing website for Caelogix, an AI software engineering company.

- **Frontend:** React (Vite) + Tailwind CSS + React Router + Framer Motion
- **Backend:** Python **FastAPI** (REST API, routers, Pydantic validation, auto-generated docs)
- **Database:** PostgreSQL + SQLAlchemy (pgvector extension for RAG embeddings)
- **Migrations:** Alembic
- **AI Chatbot:** LangChain + LangGraph agent, site-wide floating widget

```
caelogix/
├── frontend/     React + Tailwind + Vite app
├── backend/      FastAPI app, SQLAlchemy models, Alembic migrations, LangGraph chatbot
└── README.md     (this file)
```

---

## 1. Prerequisites

- Node.js 18+
- Python 3.11+
- PostgreSQL 14+ (with the ability to create the `vector` extension)
- An OpenAI API key (optional — the chatbot runs in a rule-based fallback
  mode without one, so you can develop and demo without any LLM key)

---

## 2. Database setup

Create a database, then enable pgvector:

```bash
createdb caelogix
psql caelogix -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

(Or run the provided `backend/init_db.sql` against your database.)

---

## 3. Backend setup (FastAPI)

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
# then edit .env and set:
#   DATABASE_URL       – your PostgreSQL connection string
#   OPENAI_API_KEY      – optional, enables real LLM responses in the chatbot
#   SECRET_KEY          – any random string
#   ADMIN_USERNAME / ADMIN_PASSWORD – protects GET /api/leads

# Generate and apply migrations (first time only)
alembic revision --autogenerate -m "Initial schema"
alembic upgrade head

# Seed sample blog posts + chatbot knowledge base
python seed.py

# Run the dev server (http://localhost:8000)
uvicorn main:app --reload
```

Interactive API docs are auto-generated by FastAPI at:
- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

### API endpoints

| Method | Path              | Description                                             |
|--------|-------------------|-----------------------------------------------------------|
| POST   | `/api/contact`    | Submit the contact form, stores to `contacts` table       |
| POST   | `/api/chat`       | Send a chat message, returns the LangGraph agent's reply  |
| GET    | `/api/blog`       | List blog posts                                           |
| GET    | `/api/blog/<slug>`| Get a single blog post                                    |
| GET    | `/api/leads`      | List captured leads (HTTP Basic Auth — admin only)         |
| GET    | `/api/health`     | Health check                                               |

## 4. Frontend setup (React)

```bash
cd frontend
npm install

cp .env.example .env
# VITE_API_BASE_URL defaults to http://localhost:8000/api

npm run dev
# open http://localhost:5173
```

The Vite dev server also proxies `/api/*` to `http://localhost:8000`, so the
frontend works against the local FastAPI server without any extra CORS setup
in development.

---

## 5. Building for production

```bash
# Frontend
cd frontend && npm run build     # outputs static assets to frontend/dist

# Backend
cd backend
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4
# or, with gunicorn managing uvicorn workers:
gunicorn main:app -k uvicorn.workers.UvicornWorker -w 4 -b 0.0.0.0:8000
```

Serve `frontend/dist` from your CDN/static host of choice (or behind the
same reverse proxy as the API), and point `VITE_API_BASE_URL` at your
deployed API's `/api` path at build time.

## 6. Notes on the chatbot

- The chat agent is a small **LangGraph** state graph (`backend/chatbot/agent.py`)
  with two nodes: `retrieve` (pulls relevant knowledge-base context) and
  `generate` (calls the LLM, or a rule-based fallback if no API key is set).
- The compiled graph is cached as a singleton per process via a FastAPI
  dependency (`backend/deps.py`) so it's only built once.
- Conversation history is persisted per session in `chat_sessions` /
  `chat_messages`, keyed by a `session_id` UUID generated client-side and
  stored in `sessionStorage`.
- When the agent detects strong buying intent or a request to speak with a
  person, it sets `escalate: true` in the response. The frontend widget then
  shows a link to the `/contact` page, and the backend records a `Lead`.
- The RAG knowledge base lives in `backend/chatbot/knowledge_base.py` and is
  seeded into the `knowledge_chunks` table (with embeddings, if
  `OPENAI_API_KEY` is set) by `seed.py`.

## 7. Database migrations (Alembic)

Alembic is already wired up to read `DATABASE_URL` from `.env` and to see
all models via `backend/database.py` + `backend/models.py`
(`backend/alembic/env.py` handles both).

```bash
# After changing a model in models.py:
alembic revision --autogenerate -m "Describe your change"
alembic upgrade head

# Roll back the last migration:
alembic downgrade -1
```
